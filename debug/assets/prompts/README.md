# 按钮底板提示词

底板是一张**空的**木框牌匾：只有木框、四角铆钉、空纸面，**没有任何文字/数字/图标**。
画上文字就没法复用了 —— 标签一律由 HTML 画在中间的空窗上。

## 现在的三张

| 文件名 | 中心 | 用途 |
| --- | --- | --- |
| `btn-plate.png` | 空羊皮纸 `#E8E2D0` | 常规动作（开始本地游戏、连接服务器） |
| `btn-plate-primary.png` | 蜡红 `#A3453B` | 最强动作，一屏只留一颗（首页「和人机挑战」、房间「开始游戏」） |
| `btn-plate-yes.png` | 铜绿 `#5E857A` | 肯定动作（准备、确认） |

## 再加一张的步骤

1. 复制 `btn-plate.txt`，改名成 `btn-plate-<你的名字>.txt`，只改最后一行 `Colour:` ——
   换框色和中心色，其余（构图、留白、九宫格要求）一个字都别动。
2. 图生成好放进仓库根的 `raw/`，命名 `btn-plate-<你的名字>.png`。
3. 在这两处各加一行，然后跑一遍自检：

   - `scripts/art-to-webp.py` 的 `SPECS` 和 `PLATES`
   - `scripts/check-art.mjs` 的 `SPECS`

   ```
   python scripts\art-to-webp.py
   node scripts\check-art.mjs
   ```

4. CSS 里加一条就能用，不用动 HTML 结构：

   ```css
   .btn-plate.btn-<你的名字> {
     border-image-source: url("./assets/btn-plate-<你的名字>.webp");
   }
   ```

## 生成时必须守住的几条

- 画布**正方形**（2048×2048 就行）。板子只占中间一块，四周留白。
- 板子在图里要**接近正方形**、木框四边**差不多一样厚**。
  生成成宽扁的长方形，九宫格的四角会被压成椭圆。
- 中间必须**全空**，四角要能看出是**圆角** —— 四角会被直接拿去当按钮的角。
- 不要投影、不要渐变、不要高光。这些在九宫格里会被切碎成脏边。
- 框上的木纹**顺着框走**，这样拉长之后纹理方向才对。

## 尺寸规矩（别乱改）

成品统一缩到 **512×512**，木框每边约占 17%。CSS 就按这个数字切：

```css
border-image-slice: 17.2% fill;
```

底图一旦换了尺寸或框厚比例，CSS 的切片值必须跟着改，否则会在木框外面多画一圈白边。

## 匾芯插画（btn-art-solo / btn-art-online）

首页那两张牌匾的切片不写 `fill`，中央是 CSS 自己画的：淡色纸面 + 一条从右边贴上来的
横向画带。画带现在是从首页主视觉里裁的，由 `scripts/art-btn-vignette.py` 生成：

```
python scripts\art-btn-vignette.py
```

想换成专门生成的插画，按这几点来：

- 命名 `raw/btn-art-solo.png`（人机对战）和 `raw/btn-art-online.png`（连接服务器）。
- 画布要**横向很长**，约 3.5:1 到 4.5:1。牌匾内窗只有 45px 高，方图塞进去会被压成一条缝。
- 主体放在**右半边**，左边留空。左侧会被纸色渐变盖掉给文字让位（画带本身左缘也会渐隐）。
- 背景尽量浅，和羊皮纸 `#E8E2D0` 接近；深底会让压在上面的墨色标签读不出来。
- 不要画框、不要投影、不要渐晕。

放好后改 `scripts/art-btn-vignette.py` 里 `CROPS` 的裁切比例（或直接让它读新文件），
再跑一遍脚本，然后 `node scripts/check-art.mjs` 复核尺寸。

## 棋盘底下的海图（board-sea）

棋盘后面那层海域。皮肤里已经挂好这一层了，缺文件时会退回原来的灰青渐变，
所以**不放也不影响玩**。现在的 `board-sea.webp` 是 `scripts/art-board-sea.py`
程序化画出来的占位图（浪纹 + 罗经花），随时可以被真正的插画覆盖。

要换成生成的插画：

1. 用 `board-sea.txt` 生成，画布 **2048×1152 横构图**。
2. 放成 `raw/board-sea.png`，跑：

   ```
   python scripts\art-to-webp.py
   node scripts\check-art.mjs
   ```

3. 想再画占位图就跑 `python scripts\art-board-sea.py`（会覆盖 `board-sea.webp`，
   但**不会**动 `raw/board-sea.png`；下次跑 art-to-webp.py 又会被真插画盖回来）。

生成时最要紧的一条：**中间 60% 要留空**。棋盘就压在那儿，中间东西一多，
数字和道路全都读不清。所有细节（罗经花、小船、礁石、洋流）都放在外围。
其次是**对比度必须很低**——它是一层底子，不是一张画。CSS 里还会叠一层半透明海色
统一色调，所以生成时颜色偏暖一点、偏亮一点都没关系。

## 暂时不想用某张图

把它挪到 `raw/alt/` 就行 —— 素材管线只扫 `raw/` **根目录**，子目录不参与匹配。
想用回来再挪回根目录，跑一次对应的脚本即可。当前 `raw/alt/board-sea.jpg` 就是
一张手工海图，挪走了改用程序化那张；要用它，挪回 `raw/board-sea.jpg` 再跑
`python scripts\art-to-webp.py`。

## 羊皮纸纹理砖（paper-tile）

首页那块面板的底纹，平铺用，不属于"要生成的插画"，所以没有提示词。
它由脚本生成：

```
python scripts\art-paper-tile.py
```

成品固定 256×256、无损 WebP。**必须无损** —— 逐像素级别的纸浆颗粒是有损压缩
第一个抹掉的东西，实测存成有损后高频细节从 1.27 掉到 0.01，整张砖退化成一块
平滑渐变。靠"特征只在 2px 以上"来控制体积（约 15KB）。

幅度是拿背景海图当参照定的：那张插画自己的羊皮纸标准差只有 2.39、细节 0.05，
所以纹理砖做到标准差 2.7 左右就够"融合"了；再重就会和背景打架，也会压到正文的
可读性。想更明显就调 `blotch_layer` 的 amplitude 和颗粒的 alpha。

## 港口牌上的资源图标（harbor-*，可选）

港口牌现在**只有文字**（`木2:1` / `3:1`），不配图标 —— 上一版图标既压字，缩到 12px 之后
又认不出是哪种资源。要加图标，按下面的规矩来；牌面会改成「图标在上、比例在下」两块。

画面上只有 12～14px 高，所以图标**只能有两三条主线**，多一条就糊。

- 画布**正方形**，透明底 PNG，图标居中、占宽约 70%，四周留白，不要画框。
- **一种墨色**（`#2E2A22`）均匀粗细、圆头收笔，纯线条；**不要填充、不要排线、不要阴影、
  不要渐变、不要高光**。
- 文件固定六个，名字和资源键一致，放 `raw/`：

  | 文件名 | 主体 |
  | --- | --- |
  | `harbor-wood.png` | 木材：一截原木的断面 + 一块木板 |
  | `harbor-brick.png` | 砖块：三块错开叠放的砖 |
  | `harbor-sheep.png` | 羊毛：一只卷毛羊的侧面 |
  | `harbor-wheat.png` | 小麦：一束麦穗 |
  | `harbor-ore.png` | 矿石：一块多面岩块 |
  | `harbor-any.png` | 通用 3:1：手绘问号（换成船锚也行） |

  提示词在 `prompts/harbor-*.txt`，六张只有最后一行 Subject 不同。
- 生成好跑一遍，并在这两处的 `SPECS` 各加六行（照抄 `wood-illus` 那几行）：

  ```
  python scripts\art-to-webp.py
  node scripts\check-art.mjs
  ```

- 去阿里巴巴矢量库（iconfont.cn）找也行，搜「木桩 / 砖块 / 羊 / 麦穗 / 石头 / 锚」，
  筛选**单色线条**、下载 **SVG** 最好 —— 更清晰，而且能和 `game.html` 里现成的
  `r-wood`、`r-brick`… 那套线条记法合成一套。
- 图标位置由 `debug/app.js` 的 `HARBOR_*` 常量控制：加图标时要抬高牌面
  （`HARBOR_PLATE_H`）、文字下移半格，图标放上半格。
