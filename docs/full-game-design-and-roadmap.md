# Catania 游戏设计与实现总结

本文档总结项目从第一阶段到当前版本的全部功能、实现方式、设计边界和后续路线。

## 1. 总体架构

项目采用“规则引擎 + 状态投影 + 传输层 + 渲染层”的分层结构。

```text
src/core/       规则、棋盘、状态、命令、事件、会话
src/bots/       AI 决策
src/network/    WebSocket 房间、协议、持久化
scripts/        服务器、构建、备份、复盘工具
debug/          浏览器调试与联机界面
ui-concept/     独立 UI 分支原型
tests/          Node 原生测试
```

核心原则：

- 所有游戏动作都转换为 `GameCommand`。
- 所有状态修改都经过 `dispatchCommand`。
- 每次成功命令增加一次 `version`。
- 一次命令可以产生多个事件。
- 客户端和 AI 只读取 `PlayerView`，不能直接修改状态。
- AI 使用与真人相同的合法命令入口。
- 随机结果写入可序列化状态，保证相同种子可以复现。
- 私密信息通过玩家视图投影隐藏。

## 2. 第一阶段：棋盘图与初始放置

### 功能

- 标准 19 格地图生成。
- 54 个共享顶点、72 条共享边。
- 9 个港口。
- 地形和数字满足 6、8 不相邻规则。
- 3 至 4 人游戏。
- 蛇形初始放置顺序。
- 初始道路必须连接刚放置的定居点。
- 初始定居点遵守距离规则。

### 实现

- `generateBoard(seed)` 生成地形、数字、顶点、边和港口。
- 顶点通过坐标去重，保存相邻顶点、相邻边和所属地块。
- 边保存两个端点、相邻地块、港口和道路占用。
- `createSetupOrder` 使用正向顺序加反向顺序。
- `PLACE_INITIAL_SETTLEMENT` 和 `PLACE_INITIAL_ROAD` 推进初始化步骤。
- 每个命令先校验，再克隆状态，再应用并追加事件。

### 关键文件

```text
src/core/board.js
src/core/state.js
src/core/engine.js
src/core/events.js
src/core/projection.js
```

## 3. 第二阶段：回合闭环与资源生产

### 功能

- 掷骰。
- 根据数字生产资源。
- 定居点获得 1 份，城市获得 2 份。
- 强盗所在地块不生产。
- 银行资源不足时不发放该资源。
- 结束回合和轮转玩家。

### 设计决定

- 开局每名玩家每种资源默认 1 张。
- 两个初始定居点不再额外获得相邻资源。
- 该规则是项目定制规则，不是标准版初始赠牌方式。

### 实现

- `ROLL_DICE` 使用可序列化 RNG 生成两个骰子。
- `resolveResourceProduction` 按地块汇总所有玩家需求。
- 先判断银行库存，再统一发放。
- `END_TURN` 重置回合状态并推进到下一名玩家。

## 4. 第三阶段：建造与胜利条件

### 功能

- 建造道路、定居点和城市。
- 资源成本和棋子数量限制。
- 道路必须连接自己的道路或建筑。
- 对手建筑可以切断道路。
- 定居点满足距离规则。
- 城市由自己的定居点升级。
- 获得 10 点胜利后游戏结束。

### 实现

- `BUILD_ROAD`、`BUILD_SETTLEMENT`、`BUILD_CITY` 分别校验位置、连接和资源。
- 建造消耗资源时，资源卡返回银行。
- 城市升级替换定居点并增加 1 分。
- `checkForWinner` 计算公开和私有胜利点。

### 已修复问题

早期建造和购买发展卡只从玩家手牌扣除资源，没有返还银行，长时间对局会导致资源总量消失。现在所有资源消耗都返回银行，保持 95 张资源牌守恒。

## 5. 第四阶段：强盗、弃牌和偷取

### 功能

- 掷出 7 不生产资源。
- 手牌超过 7 张的玩家依法弃掉一半。
- 所有超限玩家完成弃牌后才能移动强盗。
- 强盗阻止地块生产。
- 偷取目标只有一个时自动结算。
- 多个目标时由玩家选择。

### 实现

- `AWAITING_DISCARD`、`AWAITING_ROBBER_MOVE`、`AWAITING_STEAL_TARGET` 三个阶段串接。
- 偷取从受害者手中随机选择一张资源。
- 私密资源丢失事件只发送给受害者。

## 6. 第五阶段：发展卡、最大军队和最长道路

### 发展卡

标准 25 张：

```text
骑士 14
胜利点 5
道路建设 2
丰收之年 2
垄断 2
```

购买成本：

```text
矿石 1 + 小麦 1 + 羊毛 1
```

规则：

- 刚购买的卡当回合不能打出。
- 一回合最多打出一张发展卡。
- 骑士可以移动强盗并计入最大军队。
- 道路建设免费放置两条道路。
- 丰收之年选择两种银行资源。
- 垄断拿走所有对手的指定资源。
- 胜利点卡计入私有和最终胜利点。

### 最大军队

- 至少打出 3 张骑士。
- 只按已经打出的骑士数量计算。
- 持有但未打出的骑士不计入。
- 追平不移除当前持有者。
- 后来者必须严格更多才能夺走。

### 最长道路

- 标准要求至少 5 条连续道路。
- 使用不重复路口的连续路径计算。
- 分叉只取最长的一条。
- 不相连道路组不相加。
- 闭环按最长连续路径计算，而不是所有边相加。
- 对手建筑可以切断道路。

## 7. 第六阶段：贸易

### 银行和港口

- 默认 4:1。
- 任意港口 3:1。
- 对应资源港口 2:1。
- 港口必须由自己的定居点或城市占领。
- 银行交易立即原子完成。

### 玩家交易

- 支持多张资源换一张或多张。
- 目标玩家按座位顺序逐一回应。
- 所有目标回应后才能确认或取消。
- 成交前重新校验双方资源。
- 取消后双方手牌和银行不变。

### 已修复问题

- 修复玩家 0 作为首个回应者时被当成空值的问题。
- 修复交易步进器按钮被网格规则覆盖的问题。

## 8. 第七阶段：WebSocket 联机

### 功能

- 房间号。
- 四个真人座位或人机座位。
- 准备状态。
- 房主添加和移除人机。
- 服务器注入真实 `playerId`。
- 客户端不能伪造身份。
- 命令幂等。
- 版本冲突处理。
- 玩家级状态快照。

### 实现

- `RoomManager` 管理客户端、房间和座位。
- `RemoteGameSession` 在浏览器中处理 WebSocket。
- `processedCommands` 防止同一命令重复执行。
- `projectPlayerView` 隐藏其他玩家手牌。
- `request_sync` 先补发事件，再发送完整快照。

## 9. 第八阶段：稳定性、持久化与恢复

### 断线处理

- 真人断线后进入宽限时间。
- 超时后由 AI 临时接管。
- 玩家回来时停止接管并恢复座位。
- 房主离线时迁移给下一名已连接真人。

### SQLite 持久化

默认数据库：

```text
data/catania.sqlite
```

保存内容：

- 房间和座位。
- 最新游戏快照。
- 命令处理结果。
- 追加式 `game_events`。
- 终局战绩。

写入方式：

```text
房间快照 + 命令结果 + 事件记录
在同一个 SQLite 事务中提交
```

服务器重启后可以加载房间、恢复版本并继续对局。

### 浏览器重连

- 游客 ID 存在 `localStorage`。
- 重连令牌存在 `localStorage`。
- 使用房间邀请链接时自动尝试恢复座位。
- 对局房间默认保留 24 小时。

## 10. 观战模式

### 功能

- 观战者不占玩家座位。
- 只接收公开棋盘和公开事件。
- 不能提交游戏命令。
- 不显示具体手牌和未公开发展卡。
- 默认最多 10 名观众。
- 房主可以移出观战者。

### 实现

- `projectSpectatorView` 生成公开只读视图。
- 房间单独保存 `spectators`。
- 每次状态广播同时发送玩家和观战者快照。
- 观战者可以请求公开事件补发。

## 11. 服务器权威回合倒计时

### 功能

- 默认每个需要人工操作的阶段 60 秒。
- 倒计时由服务器计算和持久化。
- 暂停时冻结倒计时。
- 继续时恢复剩余时间。

### 超时动作

- 初始放置：自动选择合法位置。
- 等待掷骰：自动掷骰。
- 回合行动：自动结束回合。
- 弃牌：自动选择资源。
- 强盗和偷取：自动选择合法目标。
- 免费道路和丰收之年：自动选择合法命令。
- 交易回应：自动拒绝。
- 交易发起者等待：自动取消。

### 实现

- `RoomManager.scheduleTurnTimer`
- `RoomManager.handleTurnTimeout`
- `RoomManager.chooseTimeoutCommand`

## 12. 房主控制

### 房间设置

- 回合计时：关闭、30、60、90 秒。
- 是否允许观战。
- 最大观战人数。
- 是否允许断线 AI 接管。

### 对局控制

- 暂停和继续。
- 踢出玩家并转换为 AI。
- 移出观战者。
- 转移房主。

### 实现

- 设置和暂停状态写入房间快照。
- 暂停时停止 AI 调度和倒计时。
- 等待命令在暂停状态下返回 `ROOM_PAUSED`。

## 13. AI 系统

### 随机 AI

- 只从合法命令中随机选择。
- 用于初始化和测试。

### 启发式 AI

难度：

```text
easy
medium
hard
```

评估内容：

- 初始放置资源概率和资源种类。
- 道路扩展方向。
- 定居点和城市优先级。
- 强盗目标。
- 资源需求。
- 交易接受程度。
- 最长道路和最大军队。

### AI 交易限流

- 每回合最多发起一次玩家交易。
- 银行和港口交易优先。
- 只有可立即完成建造时才发起玩家交易。
- 相同报价拒绝后冷却 3 回合。
- 连续拒绝的目标冷却 2 回合。
- 同一资源组合最多提高一次报价。

## 14. 终局归档、复盘与统计

### 事件归档

每个合法命令都会产生持久事件：

- 游戏 ID。
- 序号和版本。
- 事件类型。
- 公开级别。
- 接收玩家。
- 内容。

### 复盘

- 对局结束后才能查看完整复盘。
- 支持上一条、下一条、自动播放和进度定位。
- 复盘可查看隐藏信息，因为游戏已经结束。

### 战绩

保存：

- 胜者。
- 玩家。
- 资源。
- 定居点。
- 城市。
- 道路。

命令：

```powershell
npm run replay -- 房间号
npm run stats
```

## 15. 本地数据库备份

创建备份：

```powershell
npm run db:backup
```

恢复前停止服务器：

```powershell
npm run db:restore -- data\backups\备份文件.sqlite
```

备份使用 SQLite `VACUUM INTO`，可以在服务器运行时生成一致副本。

## 16. 浏览器 UI 开发过程

### 初始界面

- SVG 棋盘。
- 顶部状态。
- 底部骰子、建造和手牌。
- 右侧联机、行动、玩家、事件。

### 可读性改进

- 右侧改成行动、玩家、房间、记录页签。
- 地形增加独立图形。
- 数字 token 增加资源标记。
- 定居点改房屋，城市改城堡轮廓。
- 道路增加深色描边。
- 行动按钮增加厚重木质效果。

### 已修复界面问题

- 合法位置被覆盖层遮挡。
- 交易步进器按钮不可点击。
- 无操作提示和实际控件同时显示。
- 复盘按钮没有即时反馈。
- `file://` 模式下 WebSocket 地址无效。

## 17. 独立 UI 概念分支

分支：

```text
codex/ui-concept
```

目录：

```text
ui-concept/
```

当前包含：

- 独立主界面原型。
- 2D 和轻微立体视角切换。
- 复古木质与羊皮纸风格。
- 地图、资源、数字、港口、棋子素材。

此分支不会修改主游戏源码。

## 18. 3D 设计方向

参考项目：

```text
bentruongclub/catan-3d
```

可以借鉴：

- Three.js 场景组织。
- 相机和 OrbitControls。
- 六边形网格转世界坐标。
- 射线拾取。
- 骰子、建筑、强盗动画。
- 程序化 Canvas 贴图。

不能直接复制：

- 无 LICENSE 仓库源码。
- 模型、贴图、音效和界面素材。

推荐模式：

- 2D 作为默认渲染。
- 3D 作为可选渲染。
- 规则状态不进入渲染层。
- 3D 只把点击转换成现有 `GameCommand`。

## 20. 当前边界和后续路线

尚未实现：

- 正式账号登录。
- 公网部署。
- 云端数据库。
- 排行榜和好友系统。
- 完整 Three.js 主渲染器。
- 最终 UI 视觉定稿。

建议顺序：

1. 完成 UI 概念稿并确定设计系统。
2. 把处理后的素材接入主界面。
3. 决定 2D 或 2D + 可选 3D 渲染路线。
4. 完成正式事件复盘 UI。
5. 增加游客升级和账号系统。
6. 部署到有持久化磁盘的服务器。
7. 后续再评估排行榜、匹配和训练型 AI。
